7. Bereich B — Produktnutzung

Dieser Bereich beantwortet:
Wie stark wird Kolai tatsächlich genutzt?

Da eure Produktschulung die zentralen Bausteine klar sichtbar macht — Landing Page / neuer Chat, Projekte, Kontexte, Web Search, Reasoning, Konnektoren, Prompt-Vorlagen, Feedback — sollte Monitoring genau darauf aufsetzen.

Empfohlene KPI-Cluster
1) User Activity
aktive Nutzer
neue Nutzer im Zeitraum
wiederkehrende Nutzer
durchschnittliche Sessions pro Nutzer
2) Chat Activity
Anzahl Chats
Anzahl Nachrichten / Prompts
Durchschnittliche Chats pro aktivem Nutzer
durchschnittliche Antwortanzahl je Chat
3) Feature Adoption
Nutzung von Projekten
Nutzung von Kontexten
Nutzung von Prompt-Vorlagen
Nutzung von Group Chats
Nutzung von Web Search
Nutzung von Reasoning
Nutzung von Konnektoren
Warum das stark ist

Du bekommst nicht nur “es wird genutzt”, sondern:

welche Teile des Produkts genutzt werden
welche Features eventuell zwar gebaut, aber kaum angenommen sind
Empfohlene Visualisierung
Für Volumina / Entwicklungen
Liniendiagramm für zeitliche Entwicklung
z. B. aktive Nutzer oder Chats pro Tag
Für Feature-Anteile
horizontale Balkendiagramme
besser als Kuchendiagramme, weil Vergleich leichter ist
Für Verteilung
optional Donut nur bei 2–4 Kategorien
z. B. Anteil Chattypen oder Anteil genutzter Features
aber nicht überall Donuts einsetzen
8. Bereich C — Pipelines & Datenverarbeitung

Das ist bei euch ein zentraler Teil, weil Kolai mehr ist als ein Chat: Es hängt an Dokumentverarbeitung, Kontextaufbau und Datenquellen. Eure Unterlagen beschreiben Kontexte als kuratierte Wissenscontainer, die über „Add Source“ erweitert und im Preview geprüft werden. Administratoren können zusätzliche Konnektoren aktivieren, um weitere Datenquellen einzubinden.

Ziel dieses Bereichs

Er beantwortet:

Kommen Dokumente und Quellen sauber rein?
Hängen Verarbeitungsschritte?

Wo entstehen Fehler?

15. Was ein UI-Designer ausdrücklich vermeiden sollte
zu technische Ops-Sicht als Default
CPU/RAM/Containerzahlen als Hauptfokus
12 verschiedene Charts ohne Priorisierung
Billing-/Kostenzahlen in denselben Haupt-Widgets
reine Tabellen ohne visuelle Priorisierung

Feedback als separater Fremdkörper statt Teil des Monitoring-Systems

16. Mein klares Zielkonzept in einem Satz

Monitoring in Kolai sollte als managementorientiertes Betriebs- und Nutzungsdashboard aufgebaut sein, das Produktadoption, Dokumenten-/Kontextpipelines, System Health, Warnungen und Feedback auf einen Blick sichtbar macht — mit wenigen starken KPIs oben und vertiefenden Diagrammen darunter.
